Why this plugin

Content written long after the last deploy — by a scheduled function, a form handler, a webhook — has to reach your templates at build time. This plugin fetches it from Netlify Blobs and keeps a local copy, so builds are fast, work offline, and degrade gracefully when the store is down.

Cached by default

Reads hit a local cache first and only reach Netlify Blobs once the entry passes its TTL. Fewer calls, faster builds, everywhere.

Never fails a build

If the store is unreachable the last good copy is served, flagged stale. Past that, an error envelope — never an exception.

Builds offline

One warm build and every build inside the TTL runs with no credentials and no network — locally and in CI alike.

One dependency

Nothing but @netlify/blobs. No build step, no runtime, pure ESM.

Installation

Install alongside Eleventy 3 or newer. Node 22.12+ is required, which is the floor set by @netlify/blobs.

Terminal
# yarn
yarn add @allons-y/eleventy-plugin-netlify-data-store

# npm
npm install @allons-y/eleventy-plugin-netlify-data-store

Configuration

Register the plugin, then wire the reads you want into global data. immediate: true runs the plugin during the config file rather than after it, which is what lets the store be destructured on the spot.

eleventy.config.js
import netlifyDataStore from "@allons-y/eleventy-plugin-netlify-data-store";

export default function (eleventyConfig) {
  let { readBlob } = eleventyConfig.addPlugin(netlifyDataStore, {
    immediate: true,
    storeName: "content",
    ttl: "1h",
  });

  eleventyConfig.addGlobalData("activity", () => readBlob("activity"));
}

Reads that reach Netlify Blobs need NETLIFY_SITE_ID and NETLIFY_TOKEN. A read served from a warm cache needs no credentials at all — which is what lets a build run offline.

Usage

Something writes an envelope — a scheduled function, a form handler, a webhook. A template reads the whole envelope back and destructures metadata and content together.

write — scheduled function
import { createDataStore } from
  "@allons-y/eleventy-plugin-netlify-data-store";

const { writeBlob } = createDataStore();

export default async () =>
  writeBlob("activity", {
    meta: { generatedAt: new Date().toISOString() },
    entries: await fetchEntries(),
  });
read — template
{% if activity.meta.error %}
  <p>Activity unavailable.</p>
{% else %}
  <p>Updated {{ activity.meta.generatedAt | generatedAt }}</p>
  {%- if activity.meta.stale %}<p>Last cached copy.</p>{%- endif %}
  <ul>
  {%- for entry in activity.entries %}
    <li>{{ entry.title }}</li>
  {%- endfor %}
  </ul>
{% endif %}

Reads resolve in order: the local cache answers while the entry is younger than ttl; otherwise Netlify Blobs does, and the result is written into the cache for the next build. If the store cannot be reached, an expired entry is served with meta.stale set rather than failing.

API & options

Three runtime functions and a date filter, all bound to the options passed at registration.

readBlob(name, storeName?)
Promise<object>

Cache first, then Netlify Blobs. Returns the full { meta, ...content } envelope, or { meta: { error } } on any failure. Never throws.

writeBlob(name, data, storeName?)
Promise<object>

Writes to the store and refreshes the cached copy. Returns { statusCode, body }, never throws.

listData(storeName?)
Promise<string[]>

The blob keys held in the store.

storeName
stringdefault: "content"

The Netlify Blobs store every call uses unless one is named explicitly.

ttl
string | numberdefault: "1h"

How long a cached entry stays fresh. Takes eleventy-fetch durations — "30m", "1h", "7d" — plus "*" to never expire and 0 to always refetch. An unparseable value throws at registration.

staleIfError
booleandefault: true

Serve an expired entry when the store is unreachable, flagged with meta.stale and meta.cacheAge. Set false to never serve data past its TTL.

cacheDir
stringdefault: ".netlify/blobs-cache"

The local, uncommitted cache. Each file wraps the value with the time it was fetched. Written by the plugin, safe to delete, and gitignored via .netlify.

siteID / token
stringdefault: from the environment

Fall back to NETLIFY_SITE_ID and NETLIFY_TOKEN. Missing credentials are logged as a configuration error, then returned as the usual envelope.

quiet
booleandefault: false

Suppress the per-read log line. Errors are always surfaced. Logging routes through Eleventy's own logger.

filterName
string | falsedefault: "generatedAt"

Name of the registered date filter for meta.generatedAt; false skips registration. Pair with locale and dateFormat.

Compatibility

  • Eleventy 3.0+ — declared as an optional peer dependency.
  • Node.js 22.12+ — the floor set by @netlify/blobs. Pure ESM, no build step.
  • Usable outside Eleventy — createDataStore() works in any Netlify Function.
  • Environment-agnostic — caching is governed by ttl, never by NODE_ENV.
