Why this plugin

Some content belongs in git, edited by a human. Some content is written by a scheduled function long after the last deploy. Both end up in the same templates — this plugin puts them behind one API so a template never has to care which is which.

Two layers, one API

Repo-managed JSON and Netlify Blobs read through the same call. Swap a name between layers without touching a template.

Never fails a build

A dead network, a missing blob, or absent credentials return an error envelope — not an exception. Templates render a fallback.

Builds offline

Development reads a local, uncommitted cache. One warm build and every build after it runs with no credentials and no network.

One dependency

Nothing but @netlify/blobs. No build step, no runtime, pure ESM.

Installation

Install alongside Eleventy 3 or newer. Node 22.12+ is required, which is the floor set by @netlify/blobs.

Terminal
# yarn
yarn add @allons-y/eleventy-plugin-netlify-data-store

# npm
npm install @allons-y/eleventy-plugin-netlify-data-store

Configuration

Register the plugin, then wire the reads you want into global data. immediate: true runs the plugin during the config file rather than after it, which is what lets the store be destructured on the spot.

eleventy.config.js
import netlifyDataStore from "@allons-y/eleventy-plugin-netlify-data-store";

export default function (eleventyConfig) {
  let { readBlob } = eleventyConfig.addPlugin(netlifyDataStore, {
    immediate: true,
    storeName: "content",
    localContent: ["team", "pages"],
  });

  eleventyConfig.addGlobalData("activity", () => readBlob("activity"));
}

Reads that reach Netlify Blobs need NETLIFY_SITE_ID and NETLIFY_TOKEN. Reads served from repo-managed JSON or a warm cache need no credentials at all.

Usage

Something writes an envelope — a scheduled function, a form handler, a webhook. A template reads the whole envelope back and destructures metadata and content together.

write — scheduled function
import { createDataStore } from
  "@allons-y/eleventy-plugin-netlify-data-store";

const { writeBlob } = createDataStore();

export default async () =>
  writeBlob("activity", {
    meta: { generatedAt: new Date().toISOString() },
    entries: await fetchEntries(),
  });
read — template
{% if activity.meta.error %}
  <p>Activity unavailable.</p>
{% else %}
  <p>Updated {{ activity.meta.generatedAt | generatedAt }}</p>
  <ul>
  {%- for entry in activity.entries %}
    <li>{{ entry.title }}</li>
  {%- endfor %}
  </ul>
{% endif %}

Reads resolve in order: a name listed in localContent comes straight from <dataDir>/<name>.json; in development the local cache answers next; otherwise the Netlify Blobs store does, and the result is written into the cache for the next offline build.

API & options

Three runtime functions and a date filter, all bound to the options passed at registration.

readBlob(name, storeName?)
Promise<object>

Returns the full { meta, ...content } envelope, or { meta: { error } } on any failure. Never throws.

writeBlob(name, data, storeName?)
Promise<object>

Returns { statusCode, body }. Refuses a repo-managed name with a 400 — that content is edited through git.

listData(storeName?)
Promise<string[]>

Blob keys in the store — or the local cache's keys in development, matching what a read would resolve.

storeName
stringdefault: "content"

The Netlify Blobs store every call uses unless one is named explicitly.

localContent
string[]default: []

Content names served from repo-managed JSON instead of Blobs. Not registered as global data — Eleventy already loads the data directory on its own.

dataDir
stringdefault: Eleventy's data directory

Where repo-managed JSON lives. Resolved on use, so a later setDataDirectory() is still honored.

cacheDir
stringdefault: ".netlify/blobs-cache"

The local, uncommitted Blobs cache. Written by the plugin, safe to delete, and gitignored via .netlify.

siteID / token
stringdefault: from the environment

Fall back to NETLIFY_SITE_ID and NETLIFY_TOKEN. Missing credentials are logged as a configuration error, then returned as the usual envelope.

quiet
booleandefault: false

Suppress the per-read log line. Errors are always surfaced. Logging routes through Eleventy's own logger.

filterName
string | falsedefault: "generatedAt"

Name of the registered date filter for meta.generatedAt; false skips registration. Pair with locale and dateFormat.

Compatibility

  • Eleventy 3.0+ — declared as an optional peer dependency.
  • Node.js 22.12+ — the floor set by @netlify/blobs. Pure ESM, no build step.
  • Usable outside Eleventy — createDataStore() works in any Netlify Function.
  • Only an explicit NODE_ENV=development reads the cache; unset is treated as production.
